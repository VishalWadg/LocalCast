# Android CI/CD & Artifact Delivery Guidelines

1. **Pre-Installed Runner SDK:** When configuring GitHub Actions on `ubuntu-latest`, do not introduce `android-actions/setup-android@v3` or invoke `sdkmanager tools`. Use the runner's pre-installed `$ANDROID_HOME` and accept licenses via `yes | sdkmanager --licenses > /dev/null 2>&1 || true`.
2. **Executable Permissions for Gradle Wrapper:** Always enforce `git update-index --chmod=+x gradlew` or run `chmod +x gradlew` within CI steps to avoid permission errors on Linux runners.
3. **Telegram 50MB Direct Binary Delivery Requirement:** Telegram Bot API (`sendDocument`) enforces a strict 50 MB (50,000,000 bytes) limit. All deliverables to Telegram must be direct binary uploads:
   - Packaging optimizations in `app/build.gradle.kts` (`packaging.jniLibs.useLegacyPackaging = true` and `defaultConfig.ndk.abiFilters` for `arm64-v8a`/`armeabi-v7a`) keep the debug APK at ~48.20 MB (`48,201,908` bytes in verified CI build `c79ff20`), leaving only **~1.80 MB headroom** under the 50,000,000-byte ceiling. Prefer Android platform APIs (e.g., `NsdManager`, `MediaProjection`) over heavy external dependencies that could push the debug APK over 50 MB.
   - In CI (`.github/workflows/android-build.yml`), perform an explicit pre-flight check asserting the staged APK exists and its file size is strictly <= 50,000,000 bytes. If it exceeds 50 MB, fail the build immediately (`exit 1`). Do NOT fall back to `sendMessage` text cards.
   - Dispatch the binary file via `sendDocument` using `curl` with retries and timeout flags.
4. **Inspect API Status:** Never execute `curl` to Telegram without verifying the JSON response. Inspect for `"ok": true` and exit with code 1 if rejected to prevent silent CI failures.
5. **AGP 9.1.1 & API 37 AAR Metadata:** Keep the `check*AarMetadata` task disable block in `app/build.gradle.kts` intact while AGP is pinned at `9.1.1` with Compose `1.12.x` / Lifecycle `2.11.0` (`minAgpVersion=9.2.0`), and maintain `testOptions.unitTests.isReturnDefaultValues = true` for JVM unit tests.
6. **JVM Unit Testing with Android/WebRTC/Compose APIs:**
   - In test doubles storing `Unsafe`-allocated Android `View`/`SurfaceViewRenderer` instances, use `IdentityHashMap` + `System.identityHashCode(...)` rather than `ConcurrentHashMap` or `$renderer` string interpolation so unmocked `hashCode()`/`equals()`/`toString()` are never invoked.
   - Invoke Jetpack Compose `Saver.save` via `with(saver) { saverScope.save(value) }` (extension receiver on `SaverScope`), and match nullable `SessionState` properties (`String?`) cleanly in Compose component signatures.
7. **Verification Without Local Android SDK:** If `ANDROID_HOME` / `local.properties` is absent locally, use `.\gradlew.bat :app:tasks --dry-run --no-daemon` for local Gradle validation and rely on GitHub Actions `:app:testDebugUnitTest` + `:app:assembleDebug` for compilation and test verification.
